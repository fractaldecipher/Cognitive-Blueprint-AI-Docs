## 🛠️ Architectural Guidelines for Developers & LLM Pipelines

If your application allows users to submit profiles without an exact birth time, follow these best practices:

### 1. Tag Profiles with an `APPROXIMATE_TIME` Metadata Flag
When a user does not know their birth time and you default to `12:00`:
```json
{
  "profile": {
    "name": "Alex",
    "birthDate": "1994-06-15",
    "birthTime": "12:00",
    "isApproximateTime": true
  }
}
```

### 2. Guardrails in LLM System Prompts
Instruct your LLM mentor to acknowledge approximation in sensitive domains:

```text
[SYSTEM DIRECTIVE: APPROXIMATE TIME DETECTED]
The user's exact birth minute is unverified (defaulted to 12:00 solar noon).
- You may speak with high confidence on: Macro career trajectories (C3), generational karma (C2), macro epochs (C4), and sleep boundaries (C5_E2).
- You MUST qualify guidance on: Decision-making authority (C1_E1), cognitive intake style (C1_E2), and specific nutritional regimens (C5_E1). Present these as hypotheses to be verified through personal self-observation rather than absolute constitutional invariants.
```

### 3. Encourage Time Retrieval
Advise users to check birth certificates, family records, or hospital archives whenever they seek deep clinical decision-making or nutritional protocols.
